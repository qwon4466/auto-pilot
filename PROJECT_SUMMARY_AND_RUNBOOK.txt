======================================================================
1. 목표 및 현재 상태
======================================================================

RC-100 Button 1 또는 desktop 키보드 1로 순찰을 시작하고 Button 4/키보드 4로
즉시 멈춘다. 공통 patrol controller는 /odom으로 1.0 m 전진량과 quaternion yaw로
우측 90도 회전량을 측정한다. 네 변을 지나면 loop count를 올리고 계속 반복한다.

Phase 1–8: ROS 2 Jazzy 데스크톱 환경, ROS 패키지, 이전 Nav2 waypoint patrol,
simulation, RC-100/OpenCR 소스 분석이 기록돼 있다. Phase 5–6 문서는 당시
Nav2 waypoint 방식의 historical 기록이다. 현재 정밀 square patrol 동작은
Nav2 task를 사용하지 않고 /odom feedback을 사용한다.

이번 보완 작업에서 완료한 코드 및 PC 검증:
- 기존 구현 확인: 과거 기본 waypoint는 약 0.6 m × 0.6 m였고 0.15 m 이동과
  90도 우회전 제어는 구현돼 있지 않았다.
- shared patrol controller: IDLE, FORWARD, TURN_RIGHT, STOPPING, ERROR 상태.
- 거리/회전 계산, 각도 wrap, safety timeout, 4변 loop count, 즉시 zero TwistStamped.
- 키보드 상단 숫자 및 숫자패드 입력, 한국어 키 안내.
- Patrol Monitor: input source, state, distance, angle, loop count, odom pose.
- Gazebo/RViz/keyboard/controller/monitor 통합 demo launch와 Path display.
- 실제 TurtleBot3 2.3.6 host patch가 FORWARD/TURN_RIGHT를 patrol ownership으로
  인식하도록 수정하고 pinned source에서 재컴파일.
- Gazebo에서 키보드 시작/정지, 1.0 m 전진(0.995–1.000 m), 90도 회전
  (89.5–89.8°), FORWARD/TURN_RIGHT STOP, 중복 START 무시, 재시작,
  두 번 연속 LOOP COUNT 증가를 확인했다.
- `colcon build --symlink-install` 성공; ROS 테스트 20개 통과, 1개 skip.

아직 실기에서 완료되지 않은 항목:
- OpenCR firmware compile/flash 및 byte 24/25/52 확인.
- Pi4 overlay 설치와 실제 controller bringup.
- 실제 RC-100 Button 1/4, 기존 방향키 수동주행 회귀 시험.
- Pi와 데스크톱 간 DDS discovery 시험, GitHub remote/push.

2. 개발 환경과 의존성
======================================================================

확인된 개발 PC: Ubuntu 24.04 noble amd64, ROS 2 Jazzy, TurtleBot3 Waffle Pi,
Gazebo Sim Harmonic 8.15, RViz2, Nav2 packages, colcon, rosdep.

빌드/테스트:

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  rosdep check --from-paths src --ignore-src
  colcon build --symlink-install
  source install/setup.bash
  colcon test --packages-select turtlebot_patrol
  colcon test-result --verbose

Ubuntu/ROS 패키지는 pip로 설치하지 않는다. 새 desktop은 ROS Jazzy APT 저장소를
설정한 뒤 `tools/install_desktop_dependencies.sh`를 실행한다. requirements.txt에는
pip 패키지만 있다. 상세 내용은 README.md와 SIMULATOR_GUIDE_KO.md를 참고한다.

======================================================================
3. 통합 Gazebo/RViz demo 실행
======================================================================

한 터미널만 사용한다. 새 셸에서 아래 명령을 실행한다.

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  export TURTLEBOT3_MODEL=waffle_pi
  ros2 launch turtlebot_patrol demo.launch.py

이 launch는 Gazebo Waffle Pi world, sensor/odom/velocity bridge, 공통 patrol
controller, 한국어 keyboard node, monitor 및 patrol_path RViz를 시작한다. VS Code
Snap의 GTK 환경이 Gazebo를 막으면 SIMULATOR_GUIDE_KO.md의 `env -u GTK_*` 명령을
사용한다.

launch가 관리하는 ROS domain은 42다. launch 터미널에 포커스를 두고:
- 숫자 1: 시작
- 숫자 4: 정지
- 숫자패드는 NumLock을 켠다.
- Ctrl+C: keyboard/demo stack 종료

`ros2 launch turtlebot_patrol patrol_sim.launch.py`도 같은 통합 실행이다.
기본 시뮬레이터 world와 GUI를 pause/resume할 수 있다. simulation clock이 멈추면
controller timer와 simulation-clock safety timeout도 함께 멈춘다.

======================================================================
4. 제어 흐름과 topic
======================================================================

KeyboardControl 또는 RC-100 host bridge -> /patrol_command -> PatrolController
-> /cmd_vel. /odom feedback으로 거리를 계산하고 /patrol_state, /patrol_telemetry,
/patrol_cycle_count, /patrol_path를 발행한다. desktop과 Pi는 이 동일한 controller
알고리즘을 공유한다. 입력 계층만 keyboard/RC로 다르다.

  /patrol_command       std_msgs/msg/String (START/STOP/RESET)
  /patrol_state         std_msgs/msg/String (IDLE/FORWARD/TURN_RIGHT/STOPPING/ERROR)
  /patrol_telemetry     std_msgs/msg/String (진행 정보 JSON)
  /patrol_cycle_count   std_msgs/msg/UInt32  (4변 완성 횟수)
  /patrol_path          nav_msgs/msg/Path   (odom 궤적)
  /cmd_vel              geometry_msgs/msg/TwistStamped
  /odom                 nav_msgs/msg/Odometry
  /scan                 sensor_msgs/msg/LaserScan

별도 터미널에서 topic을 볼 때:

  source /opt/ros/jazzy/setup.bash
  source ~/bellingham/install/setup.bash
  export ROS_DOMAIN_ID=42
  ros2 topic echo /patrol_state
  ros2 topic echo /patrol_telemetry
  ros2 topic hz /odom

데모 중 Nav2/teleop 등 다른 활성 /cmd_vel publisher를 함께 사용하지 않는다. 이
직접 주행 패턴은 장애물 회피 planner를 거치지 않으므로, 실기 시험은 평탄하고
비어 있는 통제된 공간에서 수행한다. /scan은 topic/RViz 표시로 보존된다.

======================================================================
5. STOP / loop 동작
======================================================================

STOP callback은 먼저 linear.x=0, angular.z=0인 TwistStamped를 /cmd_vel에 발행한
후 STOPPING 및 IDLE state를 발행한다. controller timer는 다음 직진 구간을 기다리지
않으므로 FORWARD와 TURN_RIGHT 어느 때나 취소할 수 있다. STOP 후 IDLE 상태라면
키보드/RC 방향키 수동모드가 다시 허용된다(실기 확인은 미완료).

FORWARD 완료 판단은 sqrt((x-start_x)^2+(y-start_y)^2), TURN_RIGHT 완료 판단은
quaternion yaw와 wrap 처리된 -pi/2 각도 차이다. 시간은 주행량 계산에 쓰지 않는다.
odom stale와 phase timeout은 센서/정체 안전용이다. 기본 목표/속도/허용오차는
1.0m, -90°, 0.15m/s, 최대 0.8rad/s(마지막 20°는 0.12rad/s), 5mm, 0.5°다.

Monitor는 MODE, STATE, INPUT DEVICE, LAST COMMAND, 목표/현재 거리, 목표/현재 각도,
설정 속도와 실제 발행 속도, LOOP COUNT, x/y/yaw를 표시한다. 네 차례 FORWARD와
TURN_RIGHT가 끝나면 LOOP COUNT가 증가한다. Gazebo에서 LOOP 1과 LOOP 2를 연속으로
확인했다.

======================================================================
6. 실제 Raspberry Pi + RC-100 진행 상황
======================================================================

준비된 patch:
- OpenCR: Button 1/4 rising-edge counter를 DYNAMIXEL control table byte 24/25,
  patrol ownership을 byte 52로 전달한다. IDLE 방향키 mapping은 기존 코드를 보존하고,
  patrol 중 manual velocity contribution은 억제한다.
- TurtleBot3 2.3.6 host: counter를 /patrol_command로 변환하고, /patrol_state의
  FORWARD/TURN_RIGHT에 따라 OpenCR ownership을 설정한다. 현재 desktop에서 pinned
  source compile 성공.

실기 전에 해야 하는 작업:
1. x86 PC에서 OpenCR Waffle sketch를 pinned patch와 의존성으로 빌드한다.
2. OpenCR firmware를 사용자 검토 후 flash하고 Button counter/control byte를 확인한다.
3. Pi4에서 tools/pi4_build_overlay.sh로 host patch + 이 repository를 빌드한다.
4. Pi bringup을 먼저 실행하고 /odom, /scan, /cmd_vel 타입을 확인한다.
5. 별도 터미널에서 `ros2 launch turtlebot_patrol patrol_robot.launch.py`를 실행한다.
6. 낮은 속도/clear floor에서 Button 1/4 및 IDLE 방향키 manual test를 수행한다.

RC Button 1/4 연결 구조는 패치에 준비돼 있지만 firmware/Pi 실제 기기 검증 전까지
완료로 표시하지 않는다. simulator domain 42와 Pi domain 0을 유지한다. Optional
domain_bridge는 /patrol_command robot→simulator, /patrol_state simulator→robot만
전달한다. /cmd_vel, /odom, /scan, /tf는 bridge하지 않는다.
