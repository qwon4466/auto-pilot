1. 프로젝트 목적과 현재 상태
======================================================================

목표는 TurtleBot3 Waffle Pi의 기존 RC-100 방향키 수동주행을 보존하면서,
RC-100 우측 Button 1로 Nav2 waypoint 반복 순찰을 시작하고 Button 4로
현재 순찰을 취소·정지하는 기능을 추가하는 것이다. 실제 RC 입력이 연결되기
전에는 ROS topic으로 START/STOP을 보내 개발 PC와 Gazebo에서 검증한다.

현재 작업 폴더는 ROS 2 workspace 겸 Git 저장소다. 실제 경로는 사용자가 처음
제안한 ~/turtlebot_patrol_ws가 아니라 ~/bellingham이다.

현재 완료된 부분:
- Phase 1: Ubuntu/ROS 2 Jazzy/TurtleBot3/Nav2/Gazebo 설치 및 환경 확인
- Phase 2: ament_python 패키지와 workspace 구성
- Phase 3: IDLE/PATROL/STOPPING/ERROR 상태 머신
- Phase 4: /patrol_command mock START/STOP/RESET 입력
- Phase 5: YAML waypoint 설정과 Nav2 반복 순찰 controller
- Phase 6: STOP의 Nav2 task 취소, 0속도 발행, Ctrl+C 종료 처리
- Phase 7: 상태 및 완료 cycle 수를 출력하는 console monitor
- Phase 8: 공식 OpenCR/RC-100/TurtleBot3 통신 소스 분석

Phase 9–12 작업 상태 (코드/문서 준비와 실제 장비 검증을 구분):
- Phase 9 코드: OpenCR 및 TurtleBot3 2.3.6용 패치 파일/적용 스크립트 추가.
  patched turtlebot3_node는 데스크탑 ROS 2 Jazzy overlay에서 컴파일 성공.
  OpenCR 펌웨어 compile/flash, Pi overlay build, RC controller 신호 검증은 미완료.
- Phase 10 코드: IDLE에서는 기존 방향키를 쓰고 PATROL 중에는 Nav2가 wheel
  control을 소유하도록 OpenCR 제어 경로를 패치. 실제 로봇에서 확인은 미완료.
- Phase 11: README/requirements 및 설치 파일을 만들고 로컬 Git commit 완료.
  GitHub remote와 push는 저장소 URL이 없어 미완료.
- Phase 12: real robot launch와 Pi overlay build script 추가. Pi에서 실행 및
  실제 지도/경유점/장애물 검증은 미완료.

중요: 현재 작업 폴더에는 기존 RC 속도를 지우고 PATROL 중 방향키 속도를
억제하도록 하는 OpenCR 패치가 준비돼 있다. 그러나 실제 로봇의 OpenCR에는
패치 firmware가 아직 compile/flash되지 않았으므로 실제 RC 연동 및 Button 4
안전 정지는 검증 완료로 간주하지 않는다.

2. 개발 환경과 ROS 패키지
======================================================================

확인된 개발 환경:
- Ubuntu 24.04 LTS (noble), amd64/x86_64
- ROS 2 Jazzy
- TurtleBot3 core 2.3.6, simulations/Gazebo 2.3.7
- Navigation2 및 nav2_simple_commander 1.3.13 계열
- Gazebo Sim 8.15.0 (Harmonic)
- OpenCR 공식 소스 검토 기준: TurtleBot3 2.3.6

ROS 패키지:
- 이름: turtlebot_patrol
- 형식: ament_python
- 위치: src/turtlebot_patrol/
- launch: patrol_sim.launch.py
- waypoint 설정: config/waypoints.yaml
- 핵심 코드: turtlebot_patrol/patrol_controller.py,
  patrol_state.py, patrol_plan.py, patrol_state_node.py,
  patrol_monitor.py, remote_command.py
- 개발 및 단계별 기록: docs/phase1-*.md ~ docs/phase8-*.md

현재 waypoint 설정은 기본 TurtleBot3 Gazebo world에서 검증한 약 0.6 m
정사각형 경로다. 시작 위치는 (-2.0, -0.5)이고 경유점은 다음 순서다.
P1 (-1.4, -0.5) -> P2 (-1.4, 0.1) -> P3 (-2.0, 0.1)
   -> P4 (-2.0, -0.5) -> 다시 P1

실제 현장 지도와 초기 pose가 다르면 이 좌표를 그대로 사용하면 안 된다.
실제 map.yaml 및 map frame 기준에 맞춰 config/waypoints.yaml을 수정해야 한다.

3. 새 터미널에서 빌드 및 기본 점검
======================================================================

터미널에서 workspace로 이동하고 ROS 환경을 읽는다.

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash

ROS dependency 점검 및 빌드:

  rosdep check --from-paths src --ignore-src
  colcon build --symlink-install
  source install/setup.bash
  ros2 pkg prefix turtlebot_patrol

정상이라면 rosdep은 다음을 출력한다.

  All system dependencies have been satisfied

패키지 prefix는 대략 다음 경로를 가리킨다.

  /home/hkl9292/bellingham/install/turtlebot_patrol

rosdep 초기화는 sudo rosdep init으로 완료됐고
/etc/ros/rosdep/sources.list.d/20-default.list가 생성된 것을 확인했다.
rosdep 갱신은 sudo 없이 실행한다.

  rosdep update

새 쉘마다 아래 두 줄을 먼저 실행한다.

  source /opt/ros/jazzy/setup.bash
  source ~/bellingham/install/setup.bash

주의: ROS 환경을 source하기 전에 rosdep check를 실행하면 launch_ros 같은
Jazzy 의존성을 찾지 못하는 오류가 날 수 있다.

5. Mock START/STOP만 검증하기 (로봇/Nav2 이동 없음)
======================================================================

터미널 1 - mock state node:

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  ros2 run turtlebot_patrol patrol_state_node

터미널 2 - monitor:

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  ros2 run turtlebot_patrol patrol_monitor

터미널 3 - mock command:

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  ros2 topic pub --once /patrol_command std_msgs/msg/String "{data: START}"
  ros2 topic pub --once /patrol_command std_msgs/msg/String "{data: STOP}"

monitor에서 IDLE, PATROL, IDLE 상태와 cycle count를 확인한다. Mock state
node는 Nav2를 실행하거나 로봇을 움직이지 않는다. STOP은 mock 환경에서
STOPPING을 거쳐 IDLE로 바로 돌아간다.

사용 가능한 명령:
- START: IDLE에서 PATROL로 전환
- STOP: PATROL을 중지 요청; mock에서는 즉시 IDLE로 완료
- RESET: ERROR를 IDLE로 초기화
- 알 수 없는 문자열은 경고 후 무시
- PATROL 중 중복 START는 무시

6. Gazebo/RViz에서 반복 순찰 확인
======================================================================

한 터미널에서 다음을 실행한다. Snap/GTK 환경 변수 충돌이 있는 데스크탑이면
아래처럼 해당 변수를 제거해서 launch한다.

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  export TURTLEBOT3_MODEL=waffle_pi
  env -u GTK_PATH -u GTK_EXE_PREFIX -u GTK_MODULES \
      -u GDK_PIXBUF_MODULEDIR -u GDK_PIXBUF_MODULE_FILE \
      -u GTK_IM_MODULE_FILE -u GIO_MODULE_DIR \
      ros2 launch turtlebot_patrol patrol_sim.launch.py

Launch는 Gazebo Waffle Pi world, 공식 TurtleBot3 Navigation2 launch,
patrol_controller 및 patrol_monitor를 실행한다. 시뮬레이션 ROS domain은
기본값 42이며 로봇의 default domain 0과 격리된다. Nav2와 초기 위치 추정이
준비될 때까지 기다릴 수 있다. RViz와 Gazebo 창에서 로봇을 관찰하고, launch
터미널의 monitor 로그에서 상태 및 cycle count를 본다.

다른 터미널에서 순찰 시작:

  source /opt/ros/jazzy/setup.bash
  source ~/bellingham/install/setup.bash
  export ROS_DOMAIN_ID=42
  ros2 topic pub --once /patrol_command std_msgs/msg/String "{data: START}"

정지/취소:

  ros2 topic pub --once /patrol_command std_msgs/msg/String "{data: STOP}"

성공하면 P1 -> P2 -> P3 -> P4 순서로 이동하고 다음 cycle을 시작한다.
STOP을 보내면 현재 Nav2 task를 cancel하고 0속도 TwistStamped를 /cmd_vel에
발행한 뒤 IDLE로 돌아온다. launch 터미널에서 Ctrl+C로 전체 시뮬레이션을
종료한다. GUI를 닫는 과정에 Gazebo/Nav2 외부 구성요소의 종료 로그가 남을 수
있으므로 종료 후 프로세스가 남지 않았는지 확인한다.

waypoint 파일을 바꿔 실행하려면:

  ros2 launch turtlebot_patrol patrol_sim.launch.py \
      waypoints_file:=/절대/경로/waypoints.yaml

확인 가능한 launch argument:

  ros2 launch turtlebot_patrol patrol_sim.launch.py --show-args

7. 상태와 ROS topic 확인
======================================================================

주요 topic:
- /patrol_command: std_msgs/msg/String, 입력 START/STOP/RESET
- /patrol_state: std_msgs/msg/String, IDLE/PATROL/STOPPING/ERROR
- /patrol_cycle_count: std_msgs/msg/UInt32, 성공적으로 완료한 전체 경로 수
- /cmd_vel: geometry_msgs/msg/TwistStamped, Nav2 이동/정지 명령

예시 확인 명령:

  ros2 topic list
  ros2 topic info /cmd_vel
  ros2 topic echo /patrol_state
ros2 topic echo /patrol_cycle_count

별도 CLI 터미널에서 simulator topic에 접속할 때는 다음을 먼저 설정한다.

  export ROS_DOMAIN_ID=42

실제 Pi의 ROS domain이 기본값 0이면 `enable_rc100_bridge:=true` launch 옵션으로
domain_bridge가 `/patrol_command`만 Pi→simulation으로 전달하고 `/patrol_state`만
simulation→Pi로 전달한다. `/cmd_vel`, `/odom`, `/scan`, `/tf`는 건너지 않는다.
domain_bridge는 별도 패키지 `ros-jazzy-domain-bridge` 설치가 필요하다.

현재 monitor는 상태와 완료 cycle 수를 로그로 출력한다. 현재 위치, 현재/다음
waypoint, 마지막 명령을 보여주는 상세 dashboard는 아직 구현하지 않았다.

8. 공식 RC-100/OpenCR 분석 결과와 하드웨어 제한
======================================================================

공식 RC100.h 기준 방향키 U/D/L/R 값은 1/2/4/8, Button 1~6은
16/32/64/128/256/512이다. 따라서 Button 1은 mask 16, Button 4는 mask 128이다.
공식 parser는 0xFF 0x55 프레임과 값/complement 쌍을 확인한다.

기존 OpenCR firmware에서는 RC 수동 속도와 host ROS cmd_vel이 합산된다. 이
프로젝트의 준비된 패치는 RC-100 Button 1/4 상승 edge를 기존 DYNAMIXEL Slave
control table의 byte 24/25 이벤트 counter로 추가하고, byte 52를 patrol wheel
ownership으로 사용한다. TurtleBot3 2.3.6의 `turtlebot3_node` host patch는
이 counter를 읽어 `/patrol_command`를 내고 `/patrol_state`에 따라 ownership을
갱신한다. 두 패치 모두 동일한 고정 upstream revision용이며 함께 설치되어야
한다. 실제 firmware compile/flash 및 serial 검증은 아직 남아 있다.

검토 기준 버전:
- TurtleBot3 tag 2.3.6, commit da785b7201d317e6e2a662e41bb3d3fd50ebd503
- OpenCR commit 68ec75d8a400949580ecf263e0105ea9743b878e
- Dynamixel2Arduino tag 0.6.1, commit 06c06f94edfc749749ee33396e4166873df9833e

기존 host는 OpenCR 주소 10~182 범위를 읽는다. 주소 사이 빈칸이라고 해서
자동으로 새 RC field가 전달되는 것은 아니다. 준비된 패치는 OpenCR Slave item
등록과 host 데이터 매핑을 함께 바꾼다. Pi에 배포하고 실제 RC command가
전달되는지 확인하는 단계가 남아 있다.

수동 방향키와 순찰 충돌 정책도 실제 로봇에서 검증해야 한다. 원래 목표는
IDLE에서 기존 수동주행을 유지하고 PATROL 중 STOP 버튼이 우선하는 것이다.
순찰 중 방향키는 wheel command에 추가되지 않으며 수동 제어는 patrol 상태가
끝난 뒤 다시 활성화된다. 이 정책은 코드에 준비돼 있으나 실제 TurtleBot에서
확인해야 한다.

12. 가장 짧은 실행 요약
======================================================================

새 터미널에서 workspace를 빌드한다:

  cd ~/bellingham
  source /opt/ros/jazzy/setup.bash
  colcon build --symlink-install
  source install/setup.bash

실제 Nav2/Gazebo 반복 순찰 simulation을 실행한다 (domain 42):

  export TURTLEBOT3_MODEL=waffle_pi
  ros2 launch turtlebot_patrol patrol_sim.launch.py

다른 터미널에서 START:

  source /opt/ros/jazzy/setup.bash
source ~/bellingham/install/setup.bash
export ROS_DOMAIN_ID=42
ros2 topic pub --once /patrol_command std_msgs/msg/String "{data: START}"

같은 방식으로 STOP:

  ros2 topic pub --once /patrol_command std_msgs/msg/String "{data: STOP}"

GTK 환경 변수 충돌로 GUI가 열리지 않을 때는 6절의 env -u 명령을 사용한다.
